A implementação atual fecha esse gap sem relabeling retroativo: uma nova rodada precisa observar NTFS, probe negativo do sandbox, Job Object, recursos e concorrência 2/1 no mesmo SHA.

O sandbox B0 é deliberadamente estreito: Python audit hook aplicado apenas aos comandos Python allowlisted das tasks da campanha. Ele permite escrita no scratch exclusivo da task e bloqueia escrita externa, subprocessos e rede. Isso não é um sandbox genérico de SO e não autoriza automaticamente comandos futuros B1 que precisem dessas capacidades.

O próximo gate é fail-fast: preflight → 82 metatestes → coverage → freeze_prepare → novo freeze → uma única rodada de `b0_release`. O alvo de saída é `RELEASE_VERDICT.status=PASS`, `release_status=LOCAL_QUALIFIED` e `HOST_QUALIFICATION.status=PASS`.
