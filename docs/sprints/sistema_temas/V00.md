# V00 — Inventário, baseline e proteção do estado atual

## O que é esta entrega

É o diagnóstico executável que antecede o Sistema de Temas. Baseline significa
uma referência identificada de como os arquivos, chamadas e resultados estavam
antes da mudança. Sprint é uma etapa de trabalho com entregas e critérios de
aceite próprios. Candidata significa que a etapa ainda precisa de revisão e
aprovação; não equivale a produto implantado.

A base desta rodada é `8744157fe9c3e0603f689fb2bcad52445e96cb41`, posterior ao
commit usado no planejamento. Ela incorpora a Concierge e possui sete etapas no
gate. A candidata R01 do PR #5 permanece separada, no commit
`af1efd14f2a688d3d3cc816ef85f5f1755e8afec`; não foi mesclada nesta sprint.

## O que muda para o usuário do Hub

Nada na aparência, nos notebooks, nos widgets ou nos resultados analíticos.
Não há ainda painel de cores ou App de gestão de temas. Você continua utilizando
o Hub como antes. Os novos arquivos são instrumentos e evidências de manutenção.

## Entregas técnicas

`tools/inventario_visual.py` reutiliza o inventário Git, o identificador de
notebooks e a extração de API pública já existentes. Lê arquivos versionados,
separa produto, derivado, ferramenta, governança e experimento; registra SHA-256,
cores, estilos, imagens, assinaturas de funções, constantes e dependências.
Não importa módulos de negócio para descobrir a API.

A busca fornece candidatos: uma ocorrência de `width` pode ser uma dimensão
visual ou outro conceito. Um código de cor em um teste não é automaticamente
uma decisão de marca. Por isso cada ocorrência nasce com `revisado: false`.
O grafo de imports absolutos resolvidos não pretende representar dependências
dinâmicas ou todos os imports relativos. A revisão deve completar essas relações.

`tools/executar_baseline_visual.py` executa os gates antigos na base e na candidata,
compara a árvore protegida e captura fixtures sintéticas de Plotly/HTML. O
validador editorial escreve QA no produto; ele é executado em worktrees descartáveis,
nunca sobre a referência que está sendo protegida.

As suítes novas exercitam as guardas de inventário e contratos observados do
legado. Não alteram o helper para tornar uma expectativa nova verdadeira.

## Como interpretar o relatório

Abra o resultado técnico indicado no README desta pasta. Confira primeiro o commit
base e o commit executado. Em seguida veja cada linha de execução. PASS vale
somente para o teste descrito. FAIL indica divergência observada; BLOQUEADO indica
que a condição de execução não foi atendida. Skips permanecem testes não executados.

Verifique a seção de arquivos protegidos: alterações em produto, derivado ou
Manual não fazem parte de V00. Confira também as pendências. Um relatório com
falhas preexistentes não deve ser apresentado como sucesso integral só porque
nenhum helper foi modificado.

A captura sintética é um JSON com categorias A/B/C, valores 10/20/5, total 35,
eixo fixo e HTML de exemplo. Os inteiros não usam aleatoriedade e exigem igualdade
exata. Esse arquivo permite comparar comportamento, mas não comprova que uma
figura ficou legível na tela do Databricks.

## Reproduzir o diagnostico

Este procedimento é para o mantenedor que já dispõe de Git, Python e das
dependências documentadas. Não é uma instrução para instalar programas no
computador corporativo nem para publicar o Hub.

Na raiz de um checkout da candidata, em PowerShell 7:

```powershell
git status --short
python -m pip install -r tools/requirements-dev.txt
pnpm --dir tools/readme_visuals install --frozen-lockfile
git worktree add --detach ../baseline-temas-v00 8744157fe9c3e0603f689fb2bcad52445e96cb41
python -B tools/executar_baseline_visual.py --base-root ../baseline-temas-v00 --output .artifacts/temas-v00-rodada-01
```

`git status --short` deve retornar vazio antes de começar. Nunca use reset ou
limpeza destrutiva para apagar trabalho de outra pessoa: escolha outro checkout.
Não use um ZIP sem histórico no lugar do clone Git; o validador editorial consulta
um commit histórico. Se o caminho de baseline já existir, escolha um novo nome;
não sobrescreva a pasta.

O runner não instala dependências. A versão de Node indicada em
`tools/readme_visuals/.node-version` e o ambiente pnpm precisam estar disponíveis.
Em Windows, criar o link de dependências na cópia descartável pode requerer
permissão para links simbólicos. Sem essa permissão, registre o bloqueio e execute
em ambiente de manutenção homologado; não contorne controles corporativos.

Para executar somente os testes novos:

```powershell
python -B tools/tests/test_inventario_visual.py
python -B tools/tests/test_visual_legado_v00.py
```

Para gerar apenas um inventário estático:

```powershell
python -B tools/inventario_visual.py --output .artifacts/inventario-v00-rodada-01.json
```

A ferramenta recusa saída fora de `.artifacts/`, sobrescrita, Git ausente,
worktree suja, quarentena versionada, arquivo simbólico e varredura sem produto.
Uma saída existente exige outro nome de rodada. Não apague evidência para fazer
a nova execução passar.

## Revisão e recuperação

O revisor independente deve selecionar sua própria amostra fora da pasta visual,
conferir todos os candidatos ativos, completar os imports dinâmicos e relativos,
reproduzir as fixtures e observar o ambiente real. A máquina não assina essa revisão.

Rodrigo deve poder entender o estado pelos documentos sem pedir ao autor que
explique verbalmente. Essa leitura ainda precisa ser testada com usuário iniciante.

Não é necessário restaurar o Databricks: nenhuma publicação ocorre. Antes do merge,
fechar a candidata mantém a main intacta. Após eventual merge, reverter somente os
commits desta sprint por revisão normal, preservando evidências e trabalho alheio.
Nunca executar comandos de remoção do produto para reverter este diagnóstico.
