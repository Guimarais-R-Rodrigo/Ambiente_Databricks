## Redundância — parcial e com falso positivo técnico

A referência objetiva congelou **>=7 padrões** de computação redundante. O auditor detecta genericamente múltiplos `count()` e acrescenta um suposto lint `SCPAP001` por acesso repetido a `corr_matrix.columns`.

Essa justificativa do lint é tecnicamente incorreta para o código observado: `corr_matrix` é um **DataFrame Pandas local**, criado após `toPandas()` e `numeric_data.corr()`. Acessar `corr_matrix.columns` não dispara RPC Spark Connect.

Logo:

- redundância real detectada: **parcial**;
- falso positivo técnico no diagnóstico de RPC: **sim**.

Há também uma falsa observação na seção de escalabilidade: o auditor afirma que a etapa numérica usa uma amostra `min(10000, total_rows)` para `describe()`, mas o notebook executa `df.select(numeric_cols).describe()` diretamente sobre o DataFrame Spark. A amostragem de aproximadamente 10 mil ocorre posteriormente na correlação.
