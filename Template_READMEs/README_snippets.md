## Orientações adicionais para desenvolver este README

### Subdivisões propostas, sem apagar as atuais

Sob Contrato de Reuso: “Como ler a assinatura”, “Como ler o retorno”, “O que posso adaptar”. Nos passos: “Onde executar cada trecho”, “Como conferir o resultado” e “Como corrigir um erro de import”. No catálogo, uma ficha padronizada por objeto sem apagar os subgrupos existentes.

### Exemplo central obrigatório

Primeiro, uma função de formatação de saída conhecida para explicar import/argumento/retorno. Depois, PSI ou split temporal com fixture completamente definida e oráculo simples. O caso avançado de PIT deve ensinar disponibilidade da informação e não apenas exibir o nome da função. Não fabricar APIs: consultar módulo e __init__.

O exemplo final deve conter pré-requisitos, local de uso, entrada completa, passos, chamada/pedido, resultado e interpretação. Código só é copiável quando os recursos e variáveis necessários foram apresentados. Acrescentar uma variação comentada para ensinar adaptação.

### Como integrar as figuras aprovadas

Manter vista explodida, mapa de categorias, jornada e ponte de reuso. Cada figura deve ser seguida por uma aplicação ao objeto escolhido para a demonstração.

As imagens ficam nos mesmos assets canônicos. Os caminhos devem ser calculados a partir do README final, não desta pasta de templates. Não inserir a informação essencial apenas no PNG.
